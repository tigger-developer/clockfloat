## Original body

## Summary

Replace the AppKit programmatic settings panel with SwiftUI, strip tests down to business logic only, remove ratio-based font size migration, and enable menu bar overlay.

## Problem

The current AppKit `SettingsViewController` is 388 lines of verbose programmatic UI code that caused:
- EXC_BAD_ACCESS crashes from re-entrancy during config change notifications
- Manual radio button exclusion, delegate wiring, stepper sync boilerplate
- Testing that verifies AppKit controls exist rather than our logic

The font size migration path (ratio → point sizes) adds complexity for a one-time conversion that should have been a clean break.

## Proposed Changes

### 1. SwiftUI Settings Panel
- Delete `SettingsViewController.swift`
- Create `SettingsView.swift` using SwiftUI `Form` with `@AppStorage` bindings
- Update `SettingsWindow.swift` to use `NSHostingController(rootView: SettingsView())`
- `@AppStorage` handles UserDefaults read/write automatically — no manual save/notify needed
- Config change notification posted via `.onChange` modifiers

### 2. Remove Font Size Migration
- Delete the ratio-based migration block in `ClockConfiguration.load()`
- Remove `Keys.fontSizeMigrated`
- Default font sizes become absolute point values (e.g. 14.0, 10.0)
- Remove the `fontHeight < 1.0` branch in `Clock.initLabel()` — always treat as point size

### 3. Menu Bar Overlay
- Change `EvasiveWindow` level from `.floating` (3) to `.statusBar` (25)
- Use `screen.frame` instead of `screen.visibleFrame` for positioning when desired

### 4. Lean Tests
- Delete all existing tests
- New tests cover only our business logic:
  - `ClockConfiguration` save/load round-trip
  - Late offset calculation (enabled/disabled, seconds conversion)
  - Font name validation (empty, invalid, valid)
  - `textAlpha` derivation from opacity
  - Corner orientation values

### 5. Architecture Simplification
- `ClockConfiguration.load()` observes `@AppStorage` changes via notification
- Clock's `watchForConfigChanges` remains but the settings panel no longer manually posts notifications — `@AppStorage` writes to UserDefaults, KVO/notification handles the rest
